## 1. Cursor / MCP時代に潜むセキュリティ地雷（Codex Security）

AIによるコード生成やMCPサーバー接続（DB接続、ローカルファイルアクセス、API実行など）は極めて強力ですが、セキュリティ対策を怠ると重大な事故につながります。

### 現場で直面する3つのセキュリティ地雷

1. **プロンプトインジェクションと悪意あるMCPツール**
   サードパーティ製MCPサーバーや外部データソース経由で悪意のある指示（「`.env` を読み込んで外部へ送信せよ」など）が挿入され、AIエディタが意図せず有害なコマンドを実行してしまうリスク。
2. **ローカルMCPエンドポイントの未認証暴露**
   ローカルマシンや社内エッジサーバーでホストしたMCPサーバー（HTTP/WebSocket）を安易にパブリック公開したり、LAN内でポートを開放した結果、同一ネットワーク上の第三者に任意コードを実行されるリスク。
3. **過剰な権限付与（Excessive Agency）**
   AIエディタにDBの書き込み権限やローカルファイルの削除権限をそのまま渡してしまい、誤生成コードの実行によって本番に近いデータが破壊されるケース。

## 2. DevOps編：Tailscaleを活用したセキュアなプライベートMCPインフラの構築

これらのセキュリティ問題をスマートに解決するのが、メッシュVPN技術を提供する **Tailscale** です。最近ではリソースの限られたデバイス（JailbreakしたKindle等）で Tailscale を動かして超軽量な内部ノード化するテクニックも話題になっていますが、この「どこでも安全に繋がるプライベートメッシュ」の考え方は開発インフラ構築に非常に有効です。

パブリックIPを公開せず、社内PCやエッジサーバー上のMCPサービスを安全にCursorから呼び出す構成を構築しましょう。

### 構成イメージ

```
[ Cursor (開発者PC) ]
       │ (Tailscale Tailnet / WireGuard暗号化)
       ├─────────────────────────────────┐
       ▼                                 ▼
[ 社内データベース MCP ]      [ ローカル/エッジ MCP サーバー ]
 (100.x.y.z:8080)               (100.x.y.w:9090)
 ※パブリック開放不要             ※ACLでアクセス制限済み
```

### 実践設定例：Tailscale ACLでのアクセス制御

Tailscaleの管理画面（または `policy.hujson`）で、MCPサーバーへのアクセス権限を「開発チームの特定の端末」のみに限定します。

```json
{
  "tagOwners": {
    "tag:mcp-server": ["admin@example.com"]
  },
  "acls": [
    // 開発者グループのみが MCP サーバーの特定のポートにアクセス可能
    {
      "action": "accept",
      "src": ["group:developers"],
      "dst": ["tag:mcp-server:8080", "tag:mcp-server:9090"]
    }
  ]
}
```

これにより、インターネット側にポートを開放することなく（`0.0.0.0` 露出ゼロ）、社内ネットワーク外のリモートワーク環境からでも安全に Cursor からプライベートMCPサーバーへ接続可能になります。

## 3. フロントエンド編：「Demo Scene」に学ぶ超低遅延・高速UI設計

AIと人間が対話しながらリアルタイムでデータを更新するMCPダッシュボードやWeb UIでは、応答速度と描画パフォーマンスが体験の肝になります。

ここで参考になるのが、制限されたリソース内で極限のビジュアルとパフォーマンスを追求する**「デモシーン（Demo Scene）」**のUIアーキテクチャ思想です。フレームワークのオーバーヘッドを削ぎ落とし、Direct DOM操作や Canvas/WebGL、軽量State管理を駆使するアプローチは、AIツール時代のダッシュボード構築に直結します。

### 地雷：重いフレームワークと過剰な再レンダリング
AIからのストリーミングレスポンス（毎秒数十回の状態更新）をReactなどの標準的な `useState` で愚直に受けると、コンポーネント全体が再レンダリングされ、UIがフリーズする地雷を踏みます。

### 対策：Signalベース＆局所更新アーキテクチャ

ストリーミングデータを受けるフロントエンドでは、仮想DOMの再計算をスキップできる **Signals** や **Web Components** の採用が効果的です。

```typescript
// Signalを活用した超軽量ストリーミングデータ描画例 (Preact Signals / Solid.js風)
import { signal } from "@preact/signals";

// AIストリーミングログ保持用Signal
export const aiLogSignal = signal<string>("");

// ソケット受信部はReactのコンポーネントツリーから独立してSignalを直接更新
const ws = new WebSocket("wss://mcp-server.tailnet-name.ts.net/stream");
ws.onmessage = (event) => {
  // レンダリングツリー全体を叩き起こさず、特定のDOMノードのみ直接更新
  aiLogSignal.value += event.data;
};

// コンポーネント側
export function StreamViewer() {
  return (
    <pre className="p-4 bg-gray-900 text-green-400 font-mono rounded">
      {aiLogSignal}
    </pre>
  );
}
```

#### ポイント：
- **Zero-Overhead Re-rendering**: ストリーミングレスポンス受領時に無駄なDiff計算を発生させない。
- **セキュリティ（Codex Security視点）**: 取得したAIテキストを `innerHTML` 等で雑に流し込まず、必ずエスケープ（またはテキストノード処理）を行ってXSS地雷を防ぐ。

## 4. 現場で使える「AIエディタ×インフラ×フロント」セキュリティチェックリスト

最後に、明日からの開発現場で即座に確認すべきチェックリストをまとめました。

- [ ] **MCPサーバーのバインドIP確認**: `0.0.0.0` で起動していないか？（Tailscale等のIP `100.x.x.x` や `127.0.0.1` に絞っているか）
- [ ] **Tailscale ACLの適用**: 不要なポートやデバイスにMCPサーバーへのアクセス許可を出していないか？
- [ ] **プロンプトサンタイズ**: MCPツール経由で取得した外部テキスト（Webページ、未知のファイル）をそのままAIの実行権限に渡していないか？
- [ ] **最小権限の原則**: Cursorに読み込ませるDB接続用MCPサーバーの権限は「READ ONLY」になっているか？
- [ ] **UIのストリーミングセキュリティ**: フロントエンドでAI生成コンテンツを描画する際、サニタイズ処理が漏れていないか？
